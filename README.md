# PPME Den Haag – Event registration (Cloudflare)

React Router 8 (SSR) on Cloudflare Workers, with D1 (SQLite), Turnstile, Resend and Cloudflare Access.
Replaces the Google Apps Script version in `../original-apps-scripts/`. Requirements live in the
"Functional Requirements & Cloudflare Migration" doc (FR ids are referenced in code comments).

## Quick start (local-first, no Cloudflare account needed)

```bash
cd web
npm install
npm run setup:local      # creates .dev.vars from the example + applies D1 migrations locally
npm run dev              # http://localhost:5173
```

Everything runs on your machine: D1 is a local SQLite file under `.wrangler/`, Turnstile uses
Cloudflare's always-pass test keys, and emails are not sent but stored in a local outbox.

| URL | What |
| --- | --- |
| http://localhost:5173/ | Redirects to the registration form of the default event |
| http://localhost:5173/admin | Committee dashboard (you are `DEV_ADMIN_EMAIL` locally, no login) |
| http://localhost:5173/admin/outbox | Every email "sent" locally, rendered with its QR codes |
| http://localhost:5173/admin/export | CSV download (one row per participant) |

Handy local commands:

```bash
npm test                 # unit + integration tests (real local D1 via wrangler getPlatformProxy)
npm run cron:local       # run the 5-minute deadline job once (dev server must be running)
npm run db:reset:local   # wipe local data and re-apply migrations
npx wrangler d1 execute DB --local --command "SELECT * FROM registrations"
```

Local tips:
- The registration window (opens Mon 16 Nov) is **not enforced** when `APP_ENV=development`; the form shows a notice.
- To test a failing bot check, set `TURNSTILE_SECRET=2x0000000000000000000000000000000AA` in `.dev.vars`.
- To send real emails locally, set `EMAIL_MODE` to `resend` in `wrangler.jsonc` and `RESEND_API_KEY` in `.dev.vars`.
- `test-output/qr-sample.png` is regenerated by `npm test` so you can scan a sample QR with your phone.

## How the important parts work

- **Quota (FR-QUO, B3):** member and non-member groups only. Seats = accepted + pending-before-deadline,
  online only (manual registrations never count). The check and the inserts run in one D1 `batch()`
  (a transaction), so concurrent submissions cannot oversell. A test fires 6 parallel families at 3 seats.
- **Email is the key (B5):** a partial unique index allows one active (accepted/pending) registration per
  email per event. Expired or rejected attempts do not block re-registering.
- **QR privacy:** the QR contains only a random 26-character ticket code (128-bit, Crockford base32).
  It is not derived from names or database ids. Only admins (and, next, scanners behind Access) can resolve it.
- **QR images:** generated in the Worker (`app/lib/qr.ts` + `app/lib/png.ts`, ~1 KB PNG each), attached inline
  (`cid:`) to the Resend email. No third-party QR service.
- **Turnstile:** widget on the form; the action verifies the token server-side before any validation or write.
- **Admin auth = identity + authorization.** Cloudflare Access proves *who* you are (the app verifies its signed JWT).
  The `admins` table decides *whether you may enter*; it is managed in **/admin/admins** (add/remove, effective
  immediately, audited). Rules: you cannot remove yourself and the last admin cannot be removed (both enforced in SQL).
  `ADMIN_EMAILS` is only a one-time seed used while the table is empty. Fails closed: no Access config, no valid JWT,
  or an email not in the table all give 401/403.

## Environments
`wrangler.jsonc` defines **`test`** (Worker `ppme-registration`: public form on workers.dev, `/admin` off), **`test-admin`** (Worker `ppme-registration-admin`: `/admin` only, fully behind
Cloudflare Access on its own workers.dev address, same database) and, later, **`production`** (the proper Worker for `event.ppmedenhaag.nl`, its own new database). Switches `ENABLE_PUBLIC` /
`ENABLE_ADMIN` (string `"false"` = off) decide what a Worker serves. Secrets are per Worker (`--env <env>`). Deploy with `npm run deploy:test`, `npm run deploy:test-admin` or
`node scripts/deploy.mjs <env>`. The full picture and the steps for both tracks are in `docs/deploy-runbook.md`; the steps below were written for the first (test) deploy.

## First deploy to Cloudflare

You need a Cloudflare account with access to the ppmedenhaag.nl zone. Run these from `web/`.
In Claude Code you can run interactive commands by prefixing them with `!`, e.g. `! npx wrangler login`.

1. **Log in to the Cloudflare CLI** (opens a browser for OAuth; one time per machine):
   ```bash
   npx wrangler login
   npx wrangler whoami        # confirm the right account
   ```
2. **Create the database in the EU** and paste the printed `database_id` into **both** D1 entries in
   `wrangler.jsonc` (top level and the environment blocks `test` / `test-admin`):
   ```bash
   npx wrangler d1 create ppme-registration --jurisdiction=eu
   npm run db:migrate:test
   ```
3. **Turnstile:** Cloudflare dashboard → Turnstile → Add widget, mode "Managed", hostnames = your production
   hostname (and `localhost` is not needed: local uses test keys). Put the **site key** in
   `env.test.vars.TURNSTILE_SITE_KEY`, and store the secret:
   ```bash
   npx wrangler secret put TURNSTILE_SECRET --env test
   ```
4. **Resend:** the ppmedenhaag.nl domain is already verified. Create an API key with "sending access" and:
   ```bash
   ```
   The bank account is public (a donation account), so it is plain configuration, not a secret: set `BANK_ACCOUNT_NAME` and
   `BANK_IBAN` in the environment's `vars`. A non-member registration is refused while they are missing or still a placeholder.
   Check `EMAIL_FROM` / `EMAIL_REPLY_TO` there too.
5. **Deploy** (refuses to run while placeholders remain):
   ```bash
   npm run deploy:test          # or: npm run deploy:test-admin
   ```
   Then add a custom domain: dashboard → Workers & Pages → ppme-registration → Settings → Domains & Routes
   (e.g. `daftar.ppmedenhaag.nl`, still to be decided).
6. **Cloudflare Access for /admin:** Zero Trust → Access → Applications → Add → Self-hosted.
   Domain = your hostname, path = `admin` (add a second path `admin/*`). Login method: One-time PIN only.
   **Policy: Allow → Include → Everyone.** This looks open but is intentional: Access only verifies that the person owns
   the email address (PIN sent to their inbox); the app then checks the `admins` table. This is what lets admins be added
   and removed in /admin/admins without touching Cloudflare. (Stricter alternative: Include → Emails = the committee, but
   then every new admin must also be added in the Access policy by hand.) Copy the application's **AUD tag** and your team domain
   (`<team>.cloudflareaccess.com`) into the environment's `vars.ACCESS_AUD` / `ACCESS_TEAM_DOMAIN`, then deploy again.
   The `*.workers.dev` URL bypasses Access, but the app still rejects it (no Access JWT = 401).
7. Smoke test in production: one member and one non-member registration, check both emails, approve the
   payment in `/admin`, then delete the test rows and reset the counter:
   ```bash
   npx wrangler d1 execute DB --remote --env test --command "DELETE FROM email_log; DELETE FROM audit_log; DELETE FROM participants; DELETE FROM registrations; UPDATE events SET payment_counter = 0;"
   ```

## Known notes

- Windows: `npm test` goes through `scripts/vitest.mjs`, which works around Vitest loading twice when the
  terminal's drive letter is lowercase (`c:\`, as VS Code sometimes does).
- Resend free tier ≈ 100 emails/day (N1). The success page always shows payment details, so a delayed email
  never blocks payment.

## Admin list: recovery

If nobody can log in (for example the seed was empty and the table is empty), add an admin straight in the database:
```bash
npx wrangler d1 execute DB --remote --env test --command "INSERT INTO admins (email, added_by, added_at) VALUES ('you@example.com', 'manual', datetime('now'))"
```
Locally: same without `--remote --env test`, or `npm run db:reset:local` (re-seeds from `ADMIN_EMAILS`).
